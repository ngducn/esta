# Reviewer 04: web UI

Scope: `/tmp/esta-thermo-wt/apps/web/src` at 5d19277, covering `components/**`, the `page.tsx` and `layout.tsx` files under `src/app`, `styles/` and `design/`, client islands and hooks. Read only. No stack, no dev server, no type check run.

## Verdict

The web UI is disciplined at the level of the line and undisciplined at the level of the pattern. Tokens, types and accessibility basics are enforced and it shows: no arbitrary pixel values, two raw hex colors (both inside `app/icon.svg`), seven type casts and no non-null assertions across components and pages. No file is near 1,000 lines; the largest is 356, a dev-only registry. The problem is that each feature phase solved the same four problems again in its own way. Those problems are uploading a document, calling a server action, giving a client island its messages, and opening a lazy sheet. The result is two upload state machines with different retry semantics. A correct `useWrite` helper sits private in one file while 19 files hand-roll the same transition, catch and error-state code. There are 17 hand-picked message subsets that the type checker cannot see, and the undo toast provider is mounted eight times, twice on the same screen. The file-length metric hides the real size smell: seven components have a single function body of 206 to 300 lines holding 6 to 12 `useState` slots. None of this is broken today, as far as I can tell without running it. All of it makes the next screen cost more than the last.

## Ratings

- **Readability: 6/10.** Files are small and comments explain the why. But a reader must learn two or three conventions for every recurring job, and the longest components hold 9 to 12 independent state slots in one 200 to 300 line body.
- **Quality: 6/10.** Type and token discipline is strong. Against that, the upload and idempotency protocol is duplicated with diverging retry behavior, translations for client islands are wired by an unchecked convention, and 16 component test files cover 143 components, so most UI behavior rests on e2e.
- **Performance: 7/10.** Bundle weight was clearly designed. Popups load lazily, pdf.js, pdf-lib and the map load dynamically, the collections board renders on the server, lists virtualize above 100 rows and loaders use React `cache`. The measurable waste is small: duplicated message namespaces in the RSC payload and one or two avoidable sequential awaits per detail page.

## Findings, ranked by severity

### 1. The document upload pipeline exists twice, with two different answers to the same idempotency question (missed simplification, highest risk)

`components/property-wizard/step-photo.tsx` (the `StepPhoto` body is 300 lines with 11 `useState`) and `components/documents/upload-sheet.tsx` (the `UploadSheet` body is 286 lines with 11 `useState`) each implement the full flow (measured). The flow picks a file, prepares it behind a race ticket ref (`picking` at step-photo.tsx:64 versus `choice` at upload-sheet.tsx:66) and runs multi-page capture with `capturing`, `capturedPages` and `leaving`. It calls `createDocumentUpload` and branches on `duplicates.length > 0`, then calls `sendPrepared` with a progress callback that writes `{ step: 'uploading', loaded, total }`, and retries on failure. Both declare their own `Phase` union with the same `editing | preparing | duplicate | uploading | failed` variants (step-photo.tsx:30-36, upload-sheet.tsx:25-30). They import the same six helpers from `@/lib/upload/prepare`, one of them renamed (`prepareFile as prepare` at upload-sheet.tsx:15). The two copies already disagree on retries. The sheet keeps the signed ticket inside the `failed` phase (`phase.ticket`, upload-sheet.tsx:30, 165-167). The wizard keeps it in a ref keyed by `sha256` with an `uploaded` flag, so a retry skips the byte transfer (step-photo.tsx:63, 136, 149-154). Either may be right. Having both means a fix to upload retries or duplicate detection lands in one place and not the other. The sheet also stores state that it could derive. `problem === 'wrongType'` is a function of `category` and `prepared.file.type`, but it is stored and re-synced by hand in `combined` and `changeCategory` (upload-sheet.tsx:89, 125-130). `title` plus `titleEdited` is an override pattern spread over two slots (upload-sheet.tsx:56-57, 128). The initial-file `useEffect` (upload-sheet.tsx:117-125) repeats the body of `choose`, and `checkFile(initialFile)` is evaluated three times (measured).

Remedy, the code-judo move: extract one `useDocumentUpload({ finish })` hook in `components/documents/` (or `lib/upload/`), backed by a reducer over a single `Phase` union that also absorbs `capturing`, `prepared` and `problem`. It owns the race ticket, the signed-ticket retry rule (pick one) and the duplicate branch. Each caller supplies only `finish(ticket, prepared)`, which is `registerDocument` for the sheet and `startPropertyWizard` for the wizard, and keeps only its own form fields. Derive `wrongType` with `acceptsMime(category, prepared.file.type)` at render and store `titleOverride: string | null`. I estimate this deletes about 100 lines from each file (inferred from the overlapping ranges step-photo.tsx:64-170 and upload-sheet.tsx:66-195) and leaves one idempotency protocol to test.

### 2. The canonical server-action helper exists, privately, and 19 files hand-roll it instead (canonical helper duplication)

`components/properties/archive-button.tsx:13-24` defines `useWrite()`, which returns `{ pending, failed, run }` and wraps `startTransition`, the `.catch` and the failure flag. It has two callers, both in that file (measured). Elsewhere `startTransition(async` appears 21 times in 19 files, and the transport-failure mapping `.catch(() => ({ ok: false, reason: 'failed' }) as const)` or a variant appears 22 times (measured with `rg -c`). Each site also declares its own error state union: `'invalid' | 'network' | null` in `legal/legal-form-shell.tsx:42`, `RentalFormErrorKind` in `rental/rental-form-error.tsx:6`, `FormError` in `LeaseForm.tsx:60`, and others. Each renders that union through its own alert markup. The inline `<p role="alert" className="flex items-start gap-2 text-body text-overdue">` with the overdue `StatusShape` is copied in 7 files (measured). Readers cannot tell which differences are intentional. One example is the hydration gate. `legal/legal-item-actions.tsx` disables delete until hydrated, but its near-twin `rental/account-actions.tsx` does not. The two files are 68 lines each, and after neutralizing the nouns `legal` and `account` only about 15 lines differ (measured with `diff`).

Remedy: promote `useWrite` to `components/use-action.ts` as `useAction<R extends { ok: boolean }>()`, returning `{ pending, result, run(action, onOk) }` and owning the `.catch` mapping. Add one `FormAlert({ message })` component. Then collapse `legal-item-actions` and `account-actions` into one `DeleteWithUndo` that takes the delete and restore actions plus an edit href.

### 3. Client-island translations are wired by an unchecked convention, in three competing shapes (boundary and type problem)

CLAUDE.md says to translate on the server and wrap a client island in a provider only when it truly needs one. In practice 65 `'use client'` files call `useTranslations` (measured), so nearly every page builds provider subsets by hand. There are 17 `<PropertyIntl>` wrapper sites, 15 `getMessages()` callers and 11 destructures of `messages.components` (measured). A server helper, `server/properties/island-messages.ts:5` (`propertyIslandIntl`), does this for 3 callers, and the other 14 sites build ad-hoc literals such as `{ leases: messages.leases, components: { money, date, status, toast } }`. The type gap is the real problem. `i18n/request.ts:13-15` types `Messages` as `typeof vi`, so `useTranslations('leases')` type-checks against the whole file. The subset handed to the provider, however, is `AbstractIntlMessages` (`components/properties/property-intl.tsx:7`). A forgotten namespace compiles and renders the raw key to Mẹ at runtime (inferred from next-intl's default fallback). No `onError` or `getMessageFallback` is configured, so nothing reports it (measured: no matches outside an unrelated image handler). The name `PropertyIntl` is also wrong, because it wraps the collections board, the document vault and the lease screens. There is a small payload cost too. `app/(app)/properties/[id]/rental/leases/[leaseId]/page.tsx:139-147` wraps two sibling islands in two providers, and each one serializes the full `leases` namespace (10,246 bytes in vi.json, measured) into the RSC payload, plus `documents` (6,110 bytes) for the second. The cost is small after compression but it is pure duplication.

Remedy: replace `PropertyIntl`, `propertyIslandIntl` and the 14 literals with one async server component, `<IntlIsland namespaces={LeaseActions.namespaces}>`. Each island exports its namespace list as a `const` tuple typed on `keyof Messages`, and the component calls `getLocale()` and `getMessages()` itself. Pages stop fetching messages, and a missing namespace becomes a type error at the island that reads it. Put sibling islands under one provider.

### 4. The undo toast provider is mounted per page, including twice on the rental tab (structural, accessibility)

`UndoToastProvider` is mounted at 8 non-dev sites (measured). These are `collections/page.tsx:73`, `documents/(vault)/layout.tsx:15`, `properties/[id]/documents/page.tsx:28`, `properties/[id]/legal/page.tsx:98`, `properties/[id]/rental/layout.tsx:11`, `properties/[id]/rental/page.tsx:77`, `components/map/properties-map.tsx:36` and `components/properties/archive-button.tsx:82`. The rental page sits under the rental layout, so that screen renders two providers. Each provider renders its own `role="region" aria-live="polite"` with the same `aria-label` (`undo-toast.tsx:28-33`), so a screen reader user meets two identical live regions (inferred from the tree; not run). The whole `rental/layout.tsx` file exists only to keep one toast alive across a navigation (its doc comment says so). Every island subset also has to carry `components.toast` for the `Hoàn tác` label.

Remedy: mount the provider once in `app/(app)/layout.tsx` and pass its two labels as props from `getTranslations` on the server, the way the shell already passes strings to `Sidebar` and `TabBar`. That deletes `rental/layout.tsx`, seven provider mounts and the `toast` entry in every message subset. Toasts then survive every in-app navigation instead of the one the layout was built for.

### 5. Two lazy sheet patterns with different accessibility and motion behavior (spaghetti growth)

`components/use-deferred-dialog.ts` is a careful primitive. It keeps the popup mounted after the first open, so `open` toggles and the exit transition can run. It preloads on hover and focus, sets `aria-haspopup` and `aria-expanded`, and passes the trigger ref as `finalFocus`. It has 2 production callers, `confirm-dialog.tsx` and `legal/ownership-sheet.tsx` (measured). Seven other sites hand-roll `lazy()` plus `useState` and mount the sheet only while it is open. These are `leases/LeaseActions.tsx` (3 sheets), `rental/unit-list.tsx` (2), `payments/RecordPaymentAction.tsx`, `documents/document-page.tsx`, `documents/document-vault.tsx`, `leases/LeaseDocuments.tsx` and `leases/LeaseForm.tsx`. Their sheets hard-code `open` and unmount on close, through `<Sheet open onOpenChange={(open) => (open ? null : onClose())}>` (6 copies, measured). The consequences are inferred and not run. The slide-out transition declared in `ui/sheet.tsx:19-21` (`data-ending-style:*`) cannot play on an unmounted popup. The `LeaseActions` trigger buttons carry neither `aria-haspopup` nor `aria-expanded` (LeaseActions.tsx:38-49). `RecordPaymentAction` adds its own module-level warm-up listener instead of the hook's preload. The sheet bodies repeat the same frame as well. The footer row class `flex flex-col-reverse gap-3 sm:flex-row sm:justify-end` appears in 13 files, and `pending ? t('saving') : t('save')`-style submit labels appear 13 times (measured).

Remedy: generalize `useDeferredDialog` into the only way to open a lazy popup, keyed so `RecordPaymentAction` can still remount per opening. Add a `FormSheet` shell that takes the title, description, error, cancel label and submit label with pending text. The five feature sheets then contain only their fields.

### 6. Business policy and form contracts in the wrong layer (boundary and layer)

The lease detail page computes lease policy inline. `app/(app)/properties/[id]/rental/leases/[leaseId]/page.tsx:37-50, 113-121` decides when a renewal is offered (`canEdit && terms !== null && start !== null && renewedBy === null && (status === 'active' || status === 'ended')`), sets the default renewal end to start plus 12 months minus a day, and uses a 24-month horizon for amendment starts with `AMEND_STARTS_SHOWN = 12`. The building blocks are pure functions in `@esta/core/lease`, but this composition is a domain rule, and only the e2e spec exercises it (measured: `renewal` appears in tests only in `e2e/lease-detail.spec.ts`, core tests of the parts, and server tests). Move it to `packages/core/src/lease` as one `leaseOffers(lease, amendments, invoices, asOf)` with unit tests. The same page also awaits `loadLeaseDocuments(summary.id)` after its `Promise.all` (page.tsx:109), although the lease id is already in the params, which costs one sequential round trip (inferred).

The legal forms hand the server an untyped record. `legal/legal-form-shell.tsx:15` declares `LegalSubmit = () => Record<string, unknown> | null`, and the server answers with a cast at `app/(app)/properties/[id]/legal/actions.ts:38` (`parsed.data as LegalInsert`). Those forms also keep one `useState` per field, with 12 slots in `legal/certificate-form.tsx:32-43` and 9 in `legal/parcel-form.tsx:34-42`. They then reassemble the row by hand in `submit` (certificate-form.tsx:47-65). Meanwhile `leases/LeaseForm.tsx:57-64` already shows the better shape: one `values` object, a typed `set<K extends keyof LeaseFormValues>` and a separate `lease-form-values.ts` module with tests. Adopt that shape for the legal forms and type `read` per kind as `z.input<typeof schema>`, and the cast and the reassembly go away.

### 7. Generic controls living in feature files, and naming drift (modularity, legibility)

`FormSelect`, the app's generic select, is defined in `components/properties/address-picker.tsx:14` and imported from there by 14 files across legal, leases, rental, documents and the wizard (measured). `TextField` and `Group` meanwhile live in `components/form-parts.tsx`. Move `FormSelect` to `form-parts.tsx`. File naming split by phase: `leases/`, `payments/` and `collections/` hold 14 PascalCase files plus a camelCase `rowActions.ts`, while every other directory uses kebab-case (measured). This is cosmetic, but it signals that later phases did not read the earlier conventions, which is the root of findings 2 to 5. A filename lint rule would hold it.

## What is genuinely good

Design-token discipline holds. `rg` finds no `[Npx]` arbitrary values, and the only raw hex colors are in `app/icon.svg`. Every arbitrary Tailwind value is a layout fraction, a selector variant or a safe-area expression. Type hygiene is strong for a UI layer, with 7 casts and 0 non-null assertions in components and pages and typed message keys through `AppConfig`. The accessibility work is deliberate. There are 46 `role="alert"` sites and `FieldMessage` pairs every error with a shape so it never relies on color. The toast live region renders in the first paint so the lazy toast lands inside a watched region. `unit-list.tsx:76-86` restores focus to a moved row after React reorders the DOM, with a comment that says why. Bundle weight was engineered. Popups and heavy libraries load on demand, `CollectionsBoard` is a server component, list virtualization loads only above 100 rows, server loaders are wrapped in React `cache`, and an e2e budget test guards `/`. Comments consistently explain the why rather than the what. `document-pager.tsx:105-107` is an example: it uses the set-during-render latch for the sticky original image correctly.
