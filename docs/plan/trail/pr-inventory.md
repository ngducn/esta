# Esta v1 PR inventory

One linear stack in id order. Branch `esta/<id lowercase>-<slug>`, for example `esta/p0-01-monorepo`. The first PR targets `main`; each later PR targets its parent's branch. `G` marks a review-gated PR (changes an interaction). Within each phase the non-gated PRs come first, so the root can merge them bottom-up before the gated batch. The phase-final PR carries the SPEC §10 exit predicate and is gated.

Seed and lane isolation (applies to every phase). The seed generator (P0-07) takes `--households N` and writes the demo household plus lane households `Gia đình Demo 1..N`, each with members `me.lane<n>@demo.esta.test` and `ryan.lane<n>@demo.esta.test` and an identical copy of the seed data. `pnpm db:reset` uses N=10 for verification. Every later schema PR extends the generator for its tables in every household.

Slots. `ESTA_SLOT=k` offsets every local Supabase and web port by 100·k (P0-02), so owners and verdict swarms run separate stacks at once.

Dev surfaces. `/dev/core` (P0-04) shows one section per pure core module, computed from canonical inputs, with expected values beside them. `/dev/agent` (P0-15) enqueues jobs and shows runs and heartbeats. Both are absent when `ESTA_ENV=production`.
