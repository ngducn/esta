# Esta v1 PR inventory

Re-cut on 2026-10-15 into vertical slices with the `vertical-slice-matrix` skill. `docs/plan/trail/slice-matrix.md` holds the matrix this list comes from. Where this list and a detailed section of `docs/plan/esta-v1-plan.md` disagree, this list wins until that phase's sections are re-cut at phase start.

Rows are in delivery order. `Seq` is the PR's position in its phase and sets its migration versions (owner-brief.md). Ids stay stable. A moved PR keeps its id, so ids are not in delivery order. A split adds a new id at the end of its phase. Under the 2026-10-15 standing orders every PR branches off `main` after the PRs it depends on merge. The changes from the 2026-10-06 inventory are in the table at the bottom.

`G` marks a PR that changes an interaction. The operator reviews its screenshots in the PR body before merge. `Opus audit` in the Proof column marks a security, money or data PR, which also gets an Opus audit lane and an interrogate pass. A pure core PR proves itself with unit and property tests and sits directly before the PR whose screen consumes it, at the scope that screen needs. No new PR adds a `/dev/*` page. `/dev/core`, `/dev/glyphs` and `/dev/components` stay as they are on `main`.

Seed and lane isolation (applies to every phase). The seed generator (P0-07) takes `--households N` and writes the demo household plus lane households `Gia đình Demo 1..N`, each with members `me.lane<n>@demo.esta.test` and `ryan.lane<n>@demo.esta.test` and an identical copy of the seed data. Every PR that adds a table extends the generator for it in every household, in the same PR (FND-7).

Slots. `ESTA_SLOT=k` offsets every local Supabase and web port by 100·k (P0-02), so owners and the verifier run separate stacks at once.

`pnpm plan:coverage` reads this file and SPEC.md. It fails when a SPEC §6 acceptance id, a north-star step, a phase exit or the Mom test has no PR here, when a phase exit PR does not cite every north-star step that its SPEC §10 exit predicate names, or when a row cites an id SPEC does not define. So a later full-run range such as P6-06's `north-star steps 1 to 9` cannot hide a step an earlier exit dropped.
